# QA 03 — Code Review Severo

Revisão sistemática do `src/`. Quebrado por severidade.

## CRITICO

1. **Main.server.luau:296 — `awardCoins` usado em `passBomb` antes de ser declarado.** `local function awardCoins` só na linha 375; o closure de `passBomb` (287) captura `awardCoins` como global nil. Todo pass dá "attempt to call a nil value (global 'awardCoins')" e o pass não premia. Fix: mover `local function awardCoins` pra antes da linha 287 (ou usar `local awardCoins; awardCoins = function(...)`).
2. **Main.server.luau:456 — mesma bug em `explode`.** `awardCoins(player, Config.COINS_SURVIVE)` resolve como global nil → crash a cada explosão. Fix: idem acima.
3. **Main.server.luau:433 — `currentModifier` usado em `explode` antes de ser declarado.** `local currentModifier` na 610; `explode` (419) captura como global. `blastMul` sempre = 1 → modificador `fat_pot` nunca aumenta explosão. Fix: declarar `local currentModifier` antes de `explode`.
4. **Main.server.luau:640-647 — `speedMul` do modificador `turbo` nunca é restaurado.** `restorers` só guarda gravity + charConn:Disconnect. Players ficam com WalkSpeed multiplicada até LoadCharacter. E `setHolder` (260) sobrescreve com `HOLDER_SPEED`, perdendo o multiplicador na mesma rodada. Fix: também guardar e restaurar WalkSpeed por character e multiplicar a partir de `NORMAL_SPEED`/`HOLDER_SPEED` quando trocar holder.
5. **Monetization.luau:103-120 — `processReceipt` não atômico.** `wasReceiptProcessed` → `grantProduct` → `markReceiptProcessed`. Se o Roblox entregar o mesmo `PurchaseId` duas vezes concorrentes (retries), ambos passam o check e creditam. Fix: marcar o receipt antes de `grantProduct` (ou usar um set local de in-flight ids).
6. **Cosmetics.luau:247 — `character.AncestryChanged:Connect` sem desconectar.** Cada `applyPet` adiciona uma nova connection; trocar pet N vezes vaza N connections (chamam `pet:Destroy()` em pets que já morreram). Fix: `:Once` ou guardar a conexão e `:Disconnect()` no próximo apply.

## ALTO

7. **Cosmetics.luau:210-214 — `CosmeticPetAnchor` cria Attachment no HumanoidRootPart; `clearNamed` só itera `character:GetChildren()`.** O Attachment em root nunca é limpo entre apply's → vazamento permanente. Fix: chamar `clearNamed(root, "CosmeticPet")` ou renomear o Anchor para fora do prefix.
8. **Main.server.luau:729 — `bomb:GetAttribute("CosmeticBase")` nunca é setado.** `Cosmetics.applyToBomb` muda `bomb.Color` mas não grava `CosmeticBase`, então o blink sempre volta ao `POTATO_COLOR` fixo — skins de batata (Ouro, Pedra, Meteoro, Melancia) somem no piscar. Fix: em `applyToBomb` após mudar cor, `bomb:SetAttribute("CosmeticBase", bomb.Color)`.
9. **Main.server.luau:529 — `SetAttribute("ArenaRadius", radius)` a cada Heartbeat (~60 Hz).** Replica cada frame enquanto a rodada roda. Fix: só setar quando mudou (ex: `math.floor(radius) ~= lastRadius`).
10. **PlayerData.luau:380 — `processedReceipts` cresce ilimitado em memória por sessão.** `markReceiptProcessed` adiciona; o compact para 128 só roda em `merge` no load. Servidor longo + muitas compras pode exceder limite de 4MB do UpdateAsync e perder o save inteiro. Fix: compactar também antes de `save`.
11. **Main.server.luau:649-657 — CharacterAdded interno em `speedMul` vaza.** `charConn:Disconnect()` desfaz o `PlayerAdded`, mas as `CharacterAdded` já conectadas para cada player continuam vivas após a rodada e aplicam `speedMul` em respawns futuros, mesmo sem modificador. Fix: guardar e desconectar todos.
12. **Main.server.luau:316/604 — `for player in alive do ... eliminate(player)` muta `alive` durante iteração.** `eliminate` seta `alive[player] = nil` dentro do loop no Heartbeat. É UB em Lua se o iterador já tiver pego o próximo. Fix: coletar vítimas numa lista, processar fora do loop.
13. **Main.server.luau runRound: `Rebirth` não checa `roundActive`.** Jogador pode dar rebirth no meio da rodada e zerar `wins`/`coins` antes do `addWin` final; coins ganhas por boost na rodada são perdidas. Fix: bloquear rebirth enquanto `roundActive=true` ou só aplicar após a próxima rodada acabar.
14. **Combat.luau:97 — `Players:GetPlayers()` a cada Heartbeat de dash.** Com N dashes simultâneos é O(N*players) por frame, cada com Combat.getRoot (FindFirstChild). Fix: iterar `alive` server-side ou atualizar hits a 30 Hz.

## MEDIO

15. **Main.server.luau:128-142 — `lastCoin` do VIPCoin não limpa em `PlayerRemoving`.** Vazamento pequeno mas eterno.
16. **Leaderboard.luau:21 — `nameCache` sem bound.** Cresce sem limite; servidor longo acumula.
17. **Codes.luau:28 — `#code > CODE_MAX_LENGTH` checado antes do `:lower():gsub("%s", "")`.** Códigos com whitespace extra podem ser rejeitados. Fix: normalizar antes de validar tamanho.
18. **Codes.luau:60-64 — `reserveGlobalUse` libera código ilimitado se `UpdateAsync` falhar em produção.** Único "dev mode" justificativa é frágil. Fix: retornar false em falha (ou tracear com rate limit).
19. **Codes.luau — redemption cross-server.** `PlayerData.hasCode` lê cache da sessão; o mesmo player em dois servers pode resgatar o mesmo código antes do save. Fix: também reservar por `player_code` no DataStore global.
20. **Main.server.luau:724 — `SetAttribute("FuseProgress", progress)` a ~20 Hz.** Replica 20 vezes/s pra todos. Fix: emitir só quando o inteiro de progresso % muda.
21. **Combat.luau:91-114 — `connection` pode ser nil se Heartbeat dispara antes da atribuição.** Em prática raro (Heartbeat fires no próximo frame), mas há a janela. Fix: guardar em tabela e checar antes de `:Disconnect()`.
22. **PlayerData.luau:9 — DataStore é `BatataQuente_v2` sem migração de `v1`.** Se o jogo já teve v1 em produção, dados antigos ficam órfãos. Fix: antes de `defaults()`, tentar `GetDataStore("BatataQuente_v1"):GetAsync` como fallback para o primeiro load.
23. **DailyReward/Quests/Shop/Rebirth `init` — PlayerAdded + GetPlayers duplica `send` em race na inicialização.** Baixo impacto além de UI update extra.
24. **Main.server.luau:587 — `Cosmetics.applyToCharacter` chamado em CharacterAdded ANTES do `PlayerData` carregar.** `task.wait(0.1)` não garante — player tem chance de aparecer sem cosmético equipado até o próximo respawn. Fix: esperar um sinal de "data loaded" (ex: `fireData` listener).
25. **Main.server.luau:781-787 — `task.delay(3, LoadCharacter)` para survivors inclui o winner que ainda está dançando a animação de VICTORY (`pcall(Animations.play, ..., VICTORY)`) — corta a dança. Fix: delay maior ou pular LoadCharacter para o winner.
26. **PlayerData.luau:441-465 — `tryClaimDaily` com clock skew (servidor que voltou no tempo) aceita elapsed negativo como < MIN (bloqueia) mas mantém `lastDailyClaim` inconsistente para saves subsequentes. Fix: clampar `lastDailyClaim = min(lastDailyClaim, now)` no load.

## BAIXO

27. **Codes.luau:31 — `:gsub("%s", "")` pega só whitespace ASCII.** Tab/espaço OK; unicode NBSP passa. Aceitável.
28. **Monetization.luau:17 — `ownsPassCache` sem TTL ou invalidação por player saindo.** Pequeno vazamento.
29. **Main.server.luau:82-86 — `teleportCharacter` sem checar humanoid vivo.** PivotTo em char morto é no-op mas sem feedback.
30. **MapBuilder.buildArena:454 — builder chamado sem pcall; erro em qualquer arena quebra `runRound` todo.**
31. **Leaderboard.luau:78-85 — `row:FindFirstChild("Name").Value` sem nil-guard; se alguém destruir o child dá crash (improvável mas defensivo).**
